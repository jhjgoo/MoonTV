# 双播放器真机验收矩阵

> 目的：在发布前用相同片源比较 ArtPlayer（默认）与 Vidstack（本地偏好或 `?player=vidstack`）的本地播放和投屏行为。此文档是人工真机记录，不以模拟结果替代。

## 执行前提

- 使用 HTTPS 部署的候选版本；桌面 Chrome/Edge 的 Google Cast 还必须能加载 `https://www.gstatic.com` 的 Cast Sender SDK。
- AirPlay/Google Cast 接收端与测试设备应处于可发现的网络，并记录网络隔离、VPN、代理或地区限制。接收端直接请求媒体 URL，不能复用浏览器 Cookie、Referer、代理/VPN 或本地 HLS loader。
- 每次测试均从同一剧集、相同起始进度开始，分别记录 ArtPlayer 和 Vidstack；投屏选择必须由用户点击触发。
- 仅收集一个公开 CORS HLS 和十个匿名化真实片源。不得在此文档、截图、Issue 或日志中写入账号、Cookie、令牌、订阅 URL、私有签名 URL 或其他凭据。
- 结果使用 `通过`、`失败`、`不支持`、`未测`；失败必须同时填写 `失败分类` 与 `可复现失败现象`。不要把未测写成通过。

## 失败分类与判定

| 分类                | 判定线索                                                      | 记录方式                                                   |
| ------------------- | ------------------------------------------------------------- | ---------------------------------------------------------- |
| CORS                | manifest、分片、字幕或密钥被跨域策略拒绝                      | 记录请求类型、HTTP 状态和浏览器/接收端提示，不记录私有 URL |
| codec               | 接收端无法解码容器、编码、音轨或 HLS 标签                     | 记录编码/容器和接收端错误                                  |
| anti-hotlink        | 接收端直连时缺少 Referer、Cookie 或特定 Header                | 标为防盗链；不得粘贴 Header/Cookie                         |
| authentication      | 媒体依赖登录、临时签名或订阅权限                              | 标为鉴权；不得粘贴令牌、账号或订阅 URL                     |
| receiver network    | 接收端离线、不同 VLAN、DNS/地区/HTTPS 或网络不可达            | 记录接收端和网络拓扑结论                                   |
| unsupported browser | 浏览器未提供所需 AirPlay、Remote Playback 或 Cast Sender 能力 | 记录浏览器版本与入口隐藏/不可用表现                        |

如果同一片源本地两种播放器均失败，先以公开 CORS HLS 复测；公开样本通过而真实片源失败时，按片源/接收端限制归类，不将其直接归因于播放器实现。

## 自动化边界与签核

- Jest/JSDOM 可以验证组件渲染、能力状态和错误处理，**不能验证真实 Google Cast 会话、设备发现、接收端解码或断线恢复成功**。
- HarmonyOS 的 Cast+、DLNA、Miracast 需要系统/原生支持；纯 Web 浏览器没有通用的主动发现与控制接口。HarmonyOS 浏览器的 Chromium UA 不能作为 Cast+、DLNA 或 Miracast 成功证据。
- 发布签核至少附上：本表的完成副本、公开基线结果、十个匿名化真实片源结果、失败分类汇总，以及任何无法完成的设备/接收端环境说明。
