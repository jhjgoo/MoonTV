# 搜索结果渐进加载设计

## 文档状态

- 日期：2026-07-21
- 状态：待书面审阅
- 影响范围：搜索页客户端加载流程
- 不影响：服务端搜索权限、播放页全量播放源搜索

## 背景

为规避 Cloudflare Pages 单次请求的子请求上限，聚合搜索已经拆成多个服务端批次。当前搜索页仍会等待全部批次完成后一次性展示结果。启用 89 个视频源、每个源最多查询 5 页时，用户需要等待多个批次全部结束，首屏反馈明显变慢。

本设计把搜索页改成渐进加载：第一批返回后立即展示；结果不足首屏时自动补批；首屏填满后，用户滚动至列表底部再加载下一批。

## 目标

- 第一批搜索结果返回后立即展示，不等待全部视频源完成。
- 第一批为空或不足一屏时，自动继续搜索后续批次。
- 内容超过一屏后，按用户滚动进度继续加载。
- 增量加载不改变成人内容权限与关键词过滤规则。
- 批次失败不阻塞后续批次，已展示结果不会因失败被清空。
- 避免重复请求、页码跳跃和旧查询响应覆盖新查询。

## 非目标

- 不修改 `/api/search` 的分页协议与服务端分批算法。
- 不引入服务端游标、搜索会话或持久化分页状态。
- 不调整播放页的播放源搜索和优选规则。
- 不改变视频卡片样式、聚合开关或搜索结果业务字段。

## 已确认决策

### 首屏补足

第一批为空或不足一屏时，自动继续加载后续批次，直到满足以下任一条件：

- 结果内容填满一屏，底部哨兵离开可视区域；
- 所有批次均已处理；
- 当前批次正在请求，等待请求结束。

连续空批次不能提前终止搜索。每个空批次完成后仍需推进下一页。

### 增量排序

采用混合排序：

- 首屏自动补足阶段：每次合并结果后统一排序。
- 滚动加载阶段：新批次内部排序后追加，不重排已有卡片。
- 去重键固定为 `source + id`，不按标题去重。

统一排序沿用当前规则：标题完全匹配优先，其次按年份和标题排序。

### 失败处理

- 单个批次失败后自动重试 1 次。
- 第二次仍失败时记录失败页码，跳过该页并继续后续批次。
- 所有可用批次处理完成后，展示「部分视频源加载失败」。
- 用户可单独重试失败批次；成功结果按当前阶段的去重和排序规则合并。
- 失败或重试不能清空已经展示的结果。

### 播放页保持不变

播放页继续使用 `fetchAllSearchResults()` 查询全部有权限的视频源，再按标题、年份和影视类型筛选候选播放源。

这里的「全量」由浏览器发起多个独立的 `/api/search?page=N` 请求。每个请求对应一次独立的 Cloudflare Worker 调用，服务端仍将上游子请求控制在安全预算内。因此播放页不会再次触发单次 Worker 的 50 个子请求限制，但仍需承担全量搜索的总耗时和请求量。本次不扩展播放页优化范围。

## 架构

### 服务端搜索接口

`GET /api/search?q=<query>&page=<page>` 保持不变：

- 每次只查询一个服务端批次。
- 每个批次重新读取当前用户权限。
- 成人源过滤发生在批次切片之前。
- 成人关键词过滤发生在批次结果返回之前。
- 响应继续返回 `results` 和 `totalPages`。
- 响应继续使用 `Cache-Control: no-store`。

前端提供的 `page` 只决定从已经过权限过滤的源列表中选择哪个批次，不能绕过成人内容权限。

### 搜索客户端

`src/lib/search.client.ts` 承担请求协议，不管理页面状态：

- 导出单批请求函数，接收查询词、页码、`fetch` 实现和 `AbortSignal`。
- 校验 HTTP 状态以及 `results`、`totalPages` 的基本结构。
- 保留 `fetchAllSearchResults()`，内部复用单批请求函数。
- 播放页继续调用 `fetchAllSearchResults()`。
- 搜索页改为调用单批请求函数。

### 渐进搜索控制层

新增独立的渐进搜索控制层，负责：

- 当前查询词和查询标识；
- 已加载结果与去重索引；
- `nextPage`、`totalPages` 和加载是否结束；
- 首屏补足模式与滚动追加模式；
- 单请求锁；
- 自动重试和失败页集合；
- 取消旧请求并拒绝旧响应写回；
- 重试失败批次。

该层不渲染 UI。搜索页通过小型、稳定的接口读取状态并触发 `loadNext()`、`retryFailed()`。

### 搜索页面

`src/app/search/page.tsx` 负责：

- 根据 URL 查询词启动或重置渐进搜索；
- 渲染首批加载、增量加载、最终空状态和失败提示；
- 渲染列表底部哨兵；
- 使用 `IntersectionObserver` 监听哨兵并调用 `loadNext()`。

观察器使用实际滚动容器 `document.body`。底部可设置小范围 `rootMargin`，让下一批在用户抵达页面底部前开始加载，减少停顿，但不能并发加载多个批次。

## 状态模型

渐进搜索包含以下状态：

| 状态              | 含义                       | 页面表现                       |
| ----------------- | -------------------------- | ------------------------------ |
| `idle`            | 尚未开始或没有查询词       | 展示搜索历史                   |
| `initial-loading` | 第 0 批尚未返回            | 页面中央加载动画               |
| `auto-filling`    | 首批已完成，但结果不足一屏 | 展示已有结果；底部提示继续搜索 |
| `ready`           | 首屏已填满，等待用户滚动   | 展示结果与底部哨兵             |
| `loading-more`    | 正在加载后续批次           | 保留结果；底部小型加载提示     |
| `exhausted`       | 所有正常批次均已处理       | 展示全部结果或最终空状态       |

失败页集合独立于主状态。`exhausted` 仍可同时存在失败页，并展示重试入口。

## 数据流

### 新查询

1. URL 中的查询词发生变化。
2. 中止旧查询的 `AbortController`。
3. 生成新的查询标识，清空结果、页码和失败集合。
4. 请求第 0 批，进入 `initial-loading`。
5. 第 0 批完成后立即展示结果。
6. 根据哨兵是否仍在视口内，进入 `auto-filling` 或 `ready`。

### 自动补足首屏

1. 哨兵在视口内，并且仍有下一批。
2. `loadNext()` 通过单请求锁后请求当前 `nextPage`。
3. 成功后推进页码、去重、合并并统一排序。
4. 浏览器完成布局后再次判断哨兵位置。
5. 哨兵仍在视口内则继续；离开视口则进入 `ready`。

该流程不依赖结果条数，因此第一批为空、连续多个批次为空时也能继续推进。

### 滚动加载

1. 用户向下浏览，哨兵进入观察区域。
2. 请求下一批并进入 `loading-more`。
3. 新批次内部排序、去重后追加到现有结果末尾。
4. 请求结束后恢复 `ready`，或在无后续批次时进入 `exhausted`。

### 失败与重试

1. 批次请求失败后立即自动重试 1 次。
2. 再次失败则将页码加入失败集合，并推进到下一批。
3. 后续批次继续正常加载。
4. 用户点击重试时，失败页按页码顺序逐个请求，避免突发并发。
5. 成功页从失败集合移除；仍失败的页保留。

## 页面反馈

- 第 0 批未完成：使用页面中央加载动画。
- 第 0 批完成且仍无结果：显示「正在继续搜索其他视频源」，不能显示最终空状态。
- 已有结果且正在补批：保留结果，在列表底部显示小型加载动画。
- 所有批次结束且结果为空：显示「未找到相关内容」。
- 所有批次结束且存在结果：显示「已加载全部结果」。
- 存在失败页：显示「部分视频源加载失败」和「重试失败批次」。

若 `IntersectionObserver` 不可用，页面应提供可点击的「加载更多」作为降级入口，不能让用户永久停留在第一批。

## 并发与性能约束

- 搜索页同一时刻最多存在 1 个批次请求。
- 哨兵重复回调不能重复请求同一页。
- 第一批完成后不再使用遮挡整个结果区的加载状态。
- 用户没有继续浏览且首屏已经填满时，不请求剩余批次。
- 新查询必须中止旧查询，减少无效上游请求。
- 播放页保留现有最多 3 个客户端批次并发，不在本次调整。

## 安全与权限

- 不在客户端接收或缓存完整视频源配置。
- 不允许客户端提交源 Key 列表决定查询范围。
- 每个分页请求都必须执行现有登录校验和成人权限过滤。
- 未开启成人权限的用户直接请求任意 `page`，都不能触发成人源请求。
- 未开启成人权限的用户不能收到命中成人关键词的内容。
- 所有权限相关响应保持 `no-store`。

## 测试方案

### 搜索客户端

- 单批请求正确传递查询词、页码和取消信号。
- 非 2xx 响应返回明确错误。
- 响应结构异常时拒绝进入页面状态。
- 全量搜索继续组合全部批次，播放页行为不变。

### 渐进搜索控制层

- 第 0 批返回后立即提供结果，不等待第 1 批。
- 第一批为空时推进下一页。
- 连续空批次不会停止自动补足。
- 重复调用 `loadNext()` 时只有 1 个在途请求。
- 首屏阶段统一排序，滚动阶段稳定追加。
- 相同 `source + id` 不重复展示。
- 失败批次自动重试 1 次，第二次失败后继续下一页。
- 失败批次可单独重试并正确合并。
- 新查询中止旧请求，旧响应不会写入新结果。

### 搜索页面

- 首批加载时展示中央加载动画。
- 首批完成后展示结果和底部增量加载状态。
- 哨兵进入视口时触发下一批。
- 首屏不足时自动连续加载，首屏填满后停止。
- 所有批次为空时才展示最终空状态。
- 不支持 `IntersectionObserver` 时展示手动加载入口。

### 服务端权限回归

- 未授权用户请求后续分页时，成人源不会被调用。
- 后续分页返回的成人关键词内容仍被过滤。
- 已授权用户可以通过后续分页访问成人源。

## 验收标准

- 搜索页在第 0 批完成后立即显示该批结果。
- 第一批为空或不足一屏时，无需用户操作即可继续搜索。
- 结果填满一屏后，不再预取用户尚未浏览的批次。
- 用户滚动至底部时自动追加下一批，已有卡片不跳位。
- 连续空批次、批次失败和失败重试均不会卡住页码。
- 新搜索不会短暂显示上一查询的结果。
- 未授权用户无法通过渐进分页绕过成人源或关键词过滤。
- 播放页候选源搜索结果与改动前一致。
