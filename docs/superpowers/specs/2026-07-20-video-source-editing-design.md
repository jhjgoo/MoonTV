# 视频源编辑设计

## 背景

管理面板目前支持新增、订阅导入、检测、启停、删除和排序视频源，但无法修改已经添加的视频源。管理员一旦填错名称、API 地址、Detail 地址或成人内容标记，只能删除后重新添加。该操作会增加误删风险，也可能改变源的排序和启用状态。

本次改造在现有视频源配置模块中增加编辑能力。编辑只面向自定义源和订阅导入源；来自 `config.json` 的内置源继续保持只读。

## 目标

- 自定义源和订阅导入源可以编辑名称、API 地址、Detail 地址、成人内容标记和启用状态。
- 视频源 Key 保持只读，避免影响排序、检测、启停、删除和历史数据关联。
- 自定义源通过一个编辑入口统一管理属性和启用状态。
- 内置源保持现有快速启停能力，不允许编辑或删除。
- 更新在原列表位置完成，不采用删除后重新添加。

## 非目标

- 不允许修改视频源 Key。
- 不允许编辑 `config.json` 内置源。
- 不迁移或重写播放记录、收藏、搜索历史等用户数据。
- 保存后不自动执行视频源检测。
- 不在本次改造中调整订阅导入、检测或排序接口。
- 不增加新的独立编辑路由。

## 已确认的产品行为

### 操作入口

不同来源的视频源显示不同操作：

| 来源                 | 操作             |
| -------------------- | ---------------- |
| 自定义源、订阅导入源 | 检测、编辑、删除 |
| `config.json` 内置源 | 检测、启用或禁用 |

自定义源不再显示独立的「启用/禁用」按钮。启用状态收进编辑模态框，与其他可修改属性一起保存。

「删除」保留在列表操作区，不放入编辑模态框，避免把危险操作混入常规编辑流程。

### 编辑模态框

点击「编辑」后打开页面内模态框，标题为「编辑视频源」，并预填当前视频源数据。

模态框使用 `role="dialog"` 和 `aria-modal="true"`，标题与对话框关联。打开时将焦点移入第一个可编辑字段，关闭后把焦点还给触发编辑的按钮。弹窗内容在窄屏下保持可滚动，不能超出可视区域。

表单包含以下字段：

- 名称：必填。
- Key：只读。
- API 地址：必填。
- Detail 地址：选填。
- 🔞 成人内容源：复选框。
- 启用此视频源：开关。

模态框底部提供「取消」和「保存修改」：

- 名称或 API 地址为空时禁用「保存修改」。
- 保存期间按钮显示「保存中…」，并禁止重复提交。
- 未在保存时，点击「取消」、关闭按钮、遮罩或按 Esc 键会关闭模态框，不提交修改。
- 保存失败时保留模态框和当前输入，展示服务端错误。
- 保存成功后关闭模态框、刷新配置，并清除该源在当前页面中的旧检测结果。

## API 设计

### 接口

继续使用现有接口：

```text
POST /api/admin/source
```

在现有操作类型中增加 `update`：

```ts
type Action = 'add' | 'update' | 'disable' | 'enable' | 'delete' | 'sort';
```

### 请求体

```json
{
  "action": "update",
  "key": "demo-source",
  "name": "示例视频源",
  "api": "https://example.com/api.php/provide/vod/",
  "detail": "https://example.com",
  "adult": false,
  "disabled": false
}
```

前端的「启用此视频源」开关与 `disabled` 取反：

- 开关开启时发送 `disabled: false`。
- 开关关闭时发送 `disabled: true`。

### 服务端处理

接口沿用现有的存储模式检查、Cookie 登录检查、站长或管理员权限判断和持久化流程。

`update` 操作按以下顺序处理：

1. 校验 `key`、`name` 和 `api` 均为非空字符串。
2. 按 `key` 查找现有视频源；找不到时返回 HTTP 404。
3. 若目标源的 `from === 'config'`，返回 HTTP 400。
4. 调用现有 `normalizeAdminSource` 修剪字符串并归一化布尔字段。
5. 在原数组位置替换条目。
6. 调用一次 `setAdminConfig` 持久化完整配置。

更新后的条目：

- 保留原 `key`。
- 保留原 `from`。
- 保留原数组位置。
- 更新 `name`、`api`、`detail`、`adult` 和 `disabled`。

服务端只把严格布尔值 `true` 归一化为开启：

```ts
adult: body.adult === true;
disabled: body.disabled === true;
```

空字符串 Detail 在归一化后保存为未设置。

### 成功响应

```json
{
  "ok": true
}
```

### 错误响应

| 场景                     | HTTP 状态码 | 错误语义               |
| ------------------------ | ----------: | ---------------------- |
| `localStorage` 模式      |         400 | 不支持管理员视频源配置 |
| 请求字段缺失或修剪后为空 |         400 | 缺少必要参数           |
| 尝试编辑内置源           |         400 | 该源不可编辑           |
| 未登录                   |         401 | Unauthorized           |
| 非站长且不是管理员       |         401 | 权限不足               |
| Key 对应的视频源不存在   |         404 | 源不存在               |
| 存储或未知异常           |         500 | 视频源管理操作失败     |

发生错误时不得修改配置，也不得调用 `setAdminConfig`。

## 前端状态与数据流

`VideoSourceConfig` 增加以下局部状态：

- 当前正在编辑的视频源副本。
- 编辑模态框是否打开。
- 保存是否进行中。

数据流如下：

1. 用户点击自定义源的「编辑」。
2. 组件复制当前视频源作为表单状态，不直接修改 `config.SourceConfig`。
3. 用户修改字段并点击「保存修改」。
4. 前端发送 `action: 'update'` 请求。
5. 请求成功后调用 `refreshConfig` 获取服务端最新配置。
6. 前端删除 `checkStates[key]`，避免继续显示基于旧 API 地址的检测结果。
7. 前端关闭模态框并清空编辑状态。

请求失败时不调用 `refreshConfig`，不清除检测结果，也不关闭模态框。

## 校验与错误处理

- 前端使用修剪后的名称和 API 地址判断是否允许保存。
- 后端重复执行必填校验，不能依赖前端。
- 保存操作不检查上游接口是否可访问。联通性仍由独立的「检测」操作负责。
- 更新不会改变拖拽排序状态之外的列表位置。
- 编辑禁用状态的视频源时，模态框应正确显示关闭的「启用此视频源」开关。
- 模态框保存期间禁止通过按钮、遮罩或 Esc 键关闭，避免用户误以为请求已取消。

## 验收标准

- 管理员可以编辑自定义源和订阅导入源，但无法修改 Key。
- 自定义源的启用状态只能从编辑模态框调整。
- 内置源无法编辑或删除，但可以继续快速启停。
- 更新后源的 Key、来源和排序位置不变。
- 保存失败不会丢失用户输入或污染前端列表。
- 旧检测结果不会在成功编辑后继续显示。
- 原有新增、订阅导入、检测、删除、启停和排序功能保持可用。
