# 用户级成人内容访问控制设计

## 目标

为每个用户增加独立的 `adult` 权限。未显式开启的用户不能搜索、查看详情或播放标记为成人内容的视频源；权限变更应在下一次请求立即生效，无需重新登录。

## 范围与规则

- 用户配置新增 `adult: boolean`，兼容历史数据：仅 `adult === true` 视为开启，其余值均按 `false` 处理。
- 新建用户、由环境变量补全的账户及历史用户默认均为 `adult: false`，包括站长和管理员。
- 视频源保持现有规则：仅源的 `adult === true` 视为成人源。
- 开启权限的用户可访问全部已启用视频源；未开启用户只能访问非成人源。
- 站长可调整所有账户（包含自身）的权限；管理员仅可调整普通用户；普通用户无自助开关。
- 既有收藏与播放记录不删除，但不得成为绕过入口：未开启用户在读取展示时看不到成人源条目；即使持有旧链接，服务端也拒绝详情与播放所需的数据请求。

## 数据与鉴权

在 `AdminConfig.UserConfig.Users` 中加入可选的 `adult?: boolean` 字段，并在配置读取、用户补全与 API 输出时归一化为布尔值。

不将该权限写入 JWT。受保护的请求根据已认证用户名重新读取当前配置并解析 `adult`，因此管理员修改后立即生效，也不会受旧 token 中权限声明滞后的影响。缺少用户记录或非布尔历史值均按未开启处理。

新增一个服务端权限 helper，负责：从当前会话解析用户、读取其即时 `adult` 状态，以及过滤/判断某个视频源是否可访问。路由只消费这个小接口，避免在搜索、详情和记录功能中散落相同的判断。

## 管理接口与界面

在现有 `/api/admin/user` action 模式中新增 `setAdultAccess`：请求体包含目标 `username` 和严格布尔值 `adult`。接口独立执行存储模式检查、鉴权、管理员权限检查及目标角色检查。

UI 在用户列表增加 `🔞` 状态列，并为可操作目标显示与当前状态相反的操作：`开启🔞` 或 `关闭🔞`。操作成功后刷新配置。站长可对自己的该项权限执行操作；其他既有敏感操作仍保留原先禁止自操作的规则。

## 内容访问链路

1. `/api/search` 在向上游发请求前排除成人源，避免无权限用户触发成人源查询或从结果中推断其存在。
2. `/api/search/one` 依据指定 source 判断；无权限访问成人源时返回 `403` 与明确错误码/消息。
3. `/api/detail` 依据指定 source 判断；无权限访问成人源时同样返回 `403`。播放页依赖详情接口，因此旧详情/播放链接无法绕过。
4. 收藏和播放记录的读取路径使用同一个可访问源过滤规则；仍保留原始数据，以便权限重新开启后自然恢复显示。

客户端将 `403` 作为“未开启成人内容访问权限”处理，不展示任何成人源数据；服务端判断才是最终安全边界。

## 错误处理

- 管理接口中 `adult` 非布尔值：`400`。
- 无会话、非管理员或管理员操作非普通用户：沿用项目既有的 `401/403` 语义。
- 无成人权限访问成人源：`403`，稳定错误文案为“未开启成人内容访问权限”。
- 源不存在、禁用或其他上游失败仍遵循现有错误语义，避免把权限错误伪装为源不存在。

## 验证

- 覆盖旧配置、缺失字段和非布尔 `adult` 的归一化测试。
- 覆盖站长（包括自己）、管理员、普通用户的权限矩阵，以及管理接口的请求校验。
- 覆盖未开启/已开启用户在聚合搜索、单源搜索、详情、收藏和记录读取中的行为。
- 手工验证：管理员开关后，目标用户无需重新登录即可在下一次请求看到或失去成人源；未开启用户用旧直达链接收到 `403`。

## 非目标

- 不增加普通用户自助开关、年龄验证或独立内容分级体系。
- 不删除已有收藏、播放记录或修改视频源订阅格式。
