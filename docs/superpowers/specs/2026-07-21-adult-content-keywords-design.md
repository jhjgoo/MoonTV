# 用户成人内容关键词过滤设计

## 目标

将原有的站点级“黄色关键词过滤”迁移为用户 `adult` 权限的一部分。未开启 `adult` 的用户不能搜索、查看、收藏或从播放记录中访问命中成人内容关键词的视频；开启权限的用户不受该关键词词库限制。

## 数据模型与迁移

`AdminConfig.SiteConfig` 新增 `AdultKeywords: string[]`。词库是站点管理员维护的共享配置，不是用户字段。

配置读取时执行一次兼容迁移：如果历史配置没有有效的 `AdultKeywords` 数组，就写入默认词库并持久化。默认词库完整保留当前 `yellowWords` 的所有词条，另加入本次确认的常见影视成人内容词，包括：`金瓶梅`、`三级片`、`成人片`、`成人影片`、`成人内容`、`18禁`、`限制级`、`A片`、`H动漫`、`H漫画`、`黄色电影`、`情色`、`性爱`、`性爱片`、`性欲`、`色欲`、`淫乱`、`淫荡`、`淫欲`、`里番`、`AV片`、`AV女优`。

词库归一化规则：仅保留非空字符串；去除首尾空白；按不区分大小写的值去重；保持首次出现的显示形式和顺序。管理员之后可自由删除、编辑或添加词条。

## 内容判定

新增纯函数内容过滤模块。它将 `title`、`type_name`、`desc` 拼为可匹配文本，使用大小写不敏感的子串匹配任一关键词。它不检查视频源名称、源 key、海报 URL 或用户搜索词。

源级与内容级控制独立叠加：

1. 未开启 `adult` 的用户先被排除所有 `source.adult === true` 的源。
2. 再从其余源返回的结果中移除命中 `AdultKeywords` 的内容。
3. 开启 `adult` 的用户跳过第 2 步，同时可访问成人源。

## 服务端访问边界

- `/api/search`：在调用上游前过滤成人源；上游结果返回后，对未开启用户移除命中关键词的项目。
- `/api/search/one`：无权访问成人源或关键词命中时返回 `403 未开启成人内容访问权限`，不调用或不暴露上游内容。
- `/api/detail`：源检查通过后获取详情；未开启用户若详情内容命中关键词，返回相同的 `403`，旧直达链接无法绕过。
- `/api/favorites` 与 `/api/playrecords`：读取全量数据时按已保存的 `title` 与 `search_title` 过滤；单条读取和新增时命中关键词则返回 `403`。删除始终允许，避免用户无法清理旧数据。

详情、收藏和记录的历史数据没有完整分类/简介时，只依据其已保存的标题字段判断；无需迁移或删除现有数据。

## 管理员设置

在现有“管理员设置”页新增“成人内容关键词”配置区：

- 顶部输入框与“添加关键词”按钮用于快速新增。
- 下方表格显示当前词条；每条有编辑和删除操作。
- 新增、编辑和删除分别调用独立的 `/api/admin/adult-keyword` 路由 action，并在成功后刷新管理员配置。
- 站长与管理员可维护；普通用户没有该入口或接口权限。
- API 严格验证请求体、归一化输入、拒绝空值与重复值。

## 移除旧站点级能力

完全移除 `NEXT_PUBLIC_DISABLE_YELLOW_FILTER`、`DisableYellowFilter`、旧 `yellow.ts` 以及搜索页上的客户端黄色词过滤。删除管理员设置中的“禁用黄色过滤器”开关、对应 API 字段和 README 环境变量说明。

历史 Redis/D1 配置中遗留的 `DisableYellowFilter` 字段不读取、不迁移且不再影响行为。所有权限相关搜索与详情响应继续使用 `Cache-Control: no-store`。

## 错误与验证

- 未开启权限的内容级拦截稳定返回 `403` 与“未开启成人内容访问权限”。
- 管理词库的无效、空白或重复输入返回 `400`；目标词不存在时编辑/删除返回 `404`。
- 自动化测试覆盖：历史配置迁移、词库归一化、关键词命中字段、管理员 CRUD 权限、搜索/单源/详情/收藏/记录的权限矩阵，以及开启 `adult` 后的放行路径。
- 验收使用 `金瓶梅`（标题命中）和原有分类词（`type_name` 命中）验证未开启用户无结果/403、开启用户正常访问。

## 非目标

- 不对关键词做语义理解、拼音变体识别或图像识别。
- 不删除数据库中的既有收藏、播放记录和视频源配置。
- 不把内容关键词用于视频源命名或站内搜索词拦截。
